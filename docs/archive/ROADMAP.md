# 开发路线与验收

> **历史归档（2026-08-15）**：这是早期 QMT/Parquet/DuckDB 目标路线，不再代表当前系统架构或下一阶段优先级。当前路线见根目录 [README](../../README.md) 的“下一阶段”。

## 架构决定

采用模块化单体与端口/适配器架构。首版不依赖券商接口；未来 Windows 上的 QMT Gateway 将是唯一加载 `xtquant` 的进程。交易引擎、GUI 和行情落盘器相互隔离。

```text
MarketDataAdapter -> EventBus -> Strategy -> TargetPosition
                                      |
                                      v
Broker callbacks <- BrokerAdapter <- OMS <- Risk <- ExecutionPlanner
                                      |
                                      v
                              append-only ledger
```

Windows 提供完整本地模式。macOS 使用同一领域核心、策略格式和 PySide6 GUI，但不直接加载 QMT；远程控制功能必须通过认证与加密通道连接 Windows 交易节点。

## 阶段

### M0：环境与零注册仿真

- 建立 Python 3.12 独立环境和依赖清单。
- 接入 BaoStock 历史数据与 AKShare 免费快照/近期分钟数据，并实现失败重试、缓存和陈旧检测。
- 完成 PaperBroker、事件模型和人工确认委托单导出。

验收：不使用账号、密码或 API Token 即可下载样例数据、运行测试和生成模拟订单。

### M1：领域核心、RuleBook 和 OMS

- 订单状态机、资金/持仓账本、T+1 可卖数量。
- 幂等客户端订单号、外发前持久化、启动对账和 SAFE_MODE。
- A 股交易时段、交易单位、价格档位、涨跌停和费用模型。

验收：事件重放得到相同状态；重复、乱序和迟到回报不会造成重复订单。

### M2：数据、回测和纸面仿真

- Parquet/ZSTD 原始与标准化行情，DuckDB 研究查询。
- 全市场保存分钟线，策略池保存 Tick；L2 获权后从首日自行归档。
- 公司行动、停复牌、成交量约束、滑点和成本。

验收：无未来数据访问；T+1、停牌、涨跌停和部分成交边界测试通过。

### M3：策略和组合层

- 普通 A 股日内信号/隔夜退出基线。
- 周度或波段目标权重基线。
- 独立的 T+0 ETF 白名单和回测配置。
- 多策略资本桶、净额和归因。

验收：同一策略代码可运行于回测、PAPER 和实时仿真；策略不能导入券商 SDK。

### M4：PAPER 委托复核与可选广发 QMT 适配

- 默认生成 PAPER 委托票据和本地/声音通知；未确认程序化报告义务前不把票据用于真实账户。
- 若以后取得正式 API 权限，再加入只读行情、账户查询、委托、撤单、回报、重连及启动对账。
- 行情陈旧、仓位、损失、报撤速率、日笔数和紧急停止。

验收：故障注入下零重复单；所有不合规委托在外发前被拒绝。

### M5：PySide6 桌面 GUI

- 总览、连接状态、K 线和盘口。
- 策略参数、回测报告、资金持仓、订单成交、风险和审计。
- 本地通知、声音告警、人工确认和实盘显式解锁。

验收：GUI 重启不影响引擎；实时、仿真和回测模式不可混淆。

### M6：观察与实盘

- 券商仿真和 shadow 至少 20 个连续交易日。
- 日终资金、持仓、委托和成交对账。
- 最小交易单位、白名单、人工值守的小资金实盘。

实盘前置：券商程序化报告确认、冻结版本、风控限额和用户单独授权。

## 数据默认值

- 零注册历史主源：BaoStock（日线及 5/15/30/60 分钟线）。
- 免费补充源：AKShare 全市场快照和近期分钟线；接口失败时只读取本地缓存并停止新信号。
- 免费公共数据不作为全自动真实委托的唯一价格源；不把普通“分时/tick 快照”描述成交易所逐笔 Level-2。
- 将来实盘主源：获正式权限后的 QMT/XtData L1；L2 只在策略研究证明增益大于费用后购买。
- 订单账本：SQLite WAL，仅放本机 SSD；不得放 OneDrive、iCloud 或 NAS。
- 行情：Parquet + ZSTD；研究：DuckDB。
